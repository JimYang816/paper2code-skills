# GitHub Operational Task Graph

Use GitHub Issues for `paper2code:evidence`, `paper2code:decision`, `paper2code:implementation`, `paper2code:validation`, `paper2code:experiment`, and `paper2code:defect`, plus `ready-for-agent`, `ready-for-human`, and `needs-info`.

Link each issue to committed Scientific Record artifacts or canonical hashes. Prefer sub-issues and native blocked-by edges. When unavailable, put `Part of #<map>` and `Blocked by: #<issue>` in the child body. Never move the only evidence, decision, contract, or result into an issue comment.
