# Vendor the minimal skill closure

This repository's `skills/` directory will contain every selected workflow skill and every transitive skill dependency, but no unrelated skills. Each Reproduction Repository receives the fixed Reproduction Core, its selected Domain Profiles, and their complete transitive closure. Skills whose upstream semantics already fit will be copied unchanged; paper-specific behavior will be added through new or deliberately adapted skills with provenance retained. A generated `skills-lock.yaml` records source identity, version or content hash, dependency edges, and whether each skill is unchanged, adapted, or new.

The initial architecture contains the lightweight `paper2code` router; setup, extraction, paper grilling, paper wayfinding, scientific prototyping, paper specification, scientific validation, CPU validation, full-run preparation, execution, evaluation, reproduction diagnosis, and underwater-acoustics profile skills. It retains the unchanged upstream grilling, domain-modeling, research, to-tickets, implement, tdd, codebase-design, code-review, and diagnosing-bugs skills. The source audit may classify a proposed paper-specific skill as new or adapted, but may not collapse its agreed responsibility into `implement`.

The Deterministic Toolkit, shared schemas, templates, and core references live in `skills/paper2code-core/` so they participate in dependency-closure copying. An `update-paper2code-skills` Stage Skill previews changes against `skills-lock.yaml`, reports conflicts and provenance changes, and requires user approval before replacing pinned skill files. It never rewrites a reproduction project's Scientific Record or implementation.
